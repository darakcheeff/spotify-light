# Генеральный план чистого портирования Spotify Desktop на Rust + Slint
**Проект:** SpotifyLight (Native Rust + Slint, Zero-Electron, Zero-WebView)  
**Версия:** 0.1.0  
**Источник портирования:** Официальный клиент Spotify Desktop (`xpui.spa`, версия 1.2.x, Rspack bundle)  
**Ресурсы:** Оригинальные шрифты (`assets/fonts/`), официальная локализация (`assets/i18n/ru.json`), токен-сетка Encore (`xpui-snapshot.css`).  
**Старый код:** Архивирован и сохранен в ветке GitHub: `archive` (`https://github.com/darakcheeff/spotify-light/tree/archive`).

---

### 2.5. Объект: МЕДИАТЕКА ПОЛЬЗОВАТЕЛЯ (`YourLibrary`)
*Функционал сайдбара:*
1. **Фильтры-чипсы (`YOUR_LIBRARY_TAG_FILTERS`):**
   - «Плейлисты», «Артисты», «Альбомы».
   - Логика: выбор чипса фильтрует отображаемый список. Слева появляется кнопка `✕` (`hitClearFilter`), сбрасывающая фильтр.
2. **Локальный фильтр/поиск (`hitFilter`):**
   - Кнопка-лупа внутри заголовка сайдбара.
   - Клик раскрывает встроенный `TextInput` («Поиск в медиатеке»).
   - Фильтрует список элементов в памяти без обращения к глобальной сети.
3. **Сортировка (`hitSort` / `sort-and-view-picker`):**
   - Варианты: «Недавние», «Недавно добавленные», «По алфавиту», «Создатель».
4. **Режимы отображения:**
   - Список (строка с обложкой, названием и подписью).
   - Компактный (только текстовые строки с плотным интервалом).
   - Сетка (квадратные/круглые карточки с названиями).

### 2.6. Объект: ГЛОБАЛЬНЫЙ ПОИСК (`GlobalSearch`)
*Функционал экрана поиска:*
1. **Поле ввода в TopBar:**
   - Placeholder: «Что хочешь включить?».
   - Автоматический переход центрального экрана на `Route::Search { query }`.
   - Кнопка быстрой очистки `✕`.
2. **Пустой запрос (Экран обзора категорий):**
   - Сетка разноцветных карточек «Обзор всех разделов» (Музыка, Подкасты, Чарты, Новые релизы).
3. **Активный поиск (Каталог Spotify):**
   - Вызов `/v1/search?q={query}&type=track,artist,album,playlist`.
   - **Блок «Лучший результат» (`TopResult`):** Крупная карточка (обложка, название, автор, бейдж типа, зеленая кнопка воспроизведения на ховере).
   - **Блок «Треки»:** Топ-4 трека в виде компактных строк таблицы (номер, иконка воспроизведения, название, исполнители, альбом, длительность, кнопка Like).
   - **Блок «Исполнители»:** Горизонтальная полка круглых аватаров с именами.
   - **Блок «Альбомы» и «Плейлисты»:** Полки квадратных карточек.

### 2.7. Объект: ПЛЕЕР И ПАНЕЛЬ УПРАВЛЕНИЯ (`NowPlayingBar`)
*Функционал нижней панели:*
1. **Информация о треке:**
   - Обложка 56x56 с кнопкой разворачивания в PiP / полноэкранный вид.
   - Кликабельное название трека и кликабельный список исполнителей.
   - Кнопка сохранения в «Любимые треки» (зеленое сердце).
2. **Контролы воспроизведения:**
   - Shuffle (`hitShuffle`): переключение случайного порядка (зеленая точка индикатора).
   - Skip Previous (`hitSkipPrevious`): переход в начало трека или к предыдущему.
   - Play/Pause (`hitPlay` / `hitPause`): белый круг 32x32 с черной иконкой.
   - Skip Next (`hitSkipNext`): переход к следующему треку в очереди.
   - Repeat (`hitRepeatEnable`, `hitRepeatOneEnable`, `hitRepeatDisable`): выключен / повтор контекста / повтор одного трека (`1`).
3. **Прогресс-бар:**
   - Форматированное время `M:SS` слева и справа.
   - Тонкая линия (4px) с заливкой `#ffffff` (зеленый `#1db954` на ховере), круглый маркер (12px), поддерживающий перетаскивание курсором (`seek`).
4. **Дополнительные кнопки справа:**
   - «Текст песни» (`desktop-npb-extra.lyricsButton`): переключает отображение караоке в правой панели.
   - «Очередь» (`desktop-npb-extra.queueButton`): открывает/закрывает правую панель очереди.
   - «Подключение к устройству» (`desktop-connect-device-picker-btn`).
   - Регулятор громкости со слайдером и иконкой состояния (High, Medium, Low, Mute).

### 2.8. Объект: ОЧЕРЕДЬ ВОСПРОИЗВЕДЕНИЯ (`QueueDrawer`)
*Функционал правой панели:*
1. **Заголовок:** текст «Очередь» и кнопка закрытия `✕`.
2. **Секция «Сейчас играет»:**
   - Крупная обложка альбома (80x80 или полноразмерная).
   - Название трека и артист.
3. **Секция «Далее в очереди»:**
   - Заголовок с указанием источника («Далее из: {Название плейлиста/альбома}»).
   - Кнопка «Очистить очередь» (`queue.clear-queue`).
   - Табличный список:
     - Колонка 1: номер в очереди или иконка играющего трека.
     - Колонка 2: миниатюра обложки 40x40.
     - Колонка 3: название трека (белый текст, жирный).
     - Колонка 4: исполнитель (серый текст `#b3b3b3`).
     - Колонка 5: время трека (`M:SS`).
     - Кнопка `•••` контекстного меню трека (со всеми действиями трека).
4. **Секция «Недавно прослушано»:**
   - Заполняется из эндпоинта `/v1/me/player/recently-played`.

## 3. Аудио-подсистема: Архитектурный анализ Kinrox и варианты для Linux

### 3.1. Как устроен звук и дешифрование в Kinrox (https://github.com/awaik/Kinrox)
При прямом исследовании кодовой базы Kinrox вскрылась следующая архитектура:
1. **Режим 1: Spotify Connect (`SpotifyConnectMusicEngine.swift`) — базовый режим Kinrox:**
   * Аудиопоток не декодируется самописным кодом. Дословно из исходников Kinrox:  
     `"Audio stays in Spotify. The complete occurrence timeline is mirrored into our private helper."`
   * Kinrox выступает сверхбыстрым нативным контроллером (Swift + SQLite кэш), управляющим воспроизведением через Spotify Web API (`PUT /v1/me/player/play`, пауза, громкость, очередь), при этом статус-бар, таймлайн и обложки отрисовываются нативно локально.
2. **Режим 2: Soloist (`SoloistMusicEngine.swift` / `SoloistInstaller.swift`) — режим с v0.5.0:**
   * Для автономного воспроизведения без запущенного официального приложения Kinrox скачивает официальный проприетарный бинарный демон **Soloist** (`com.spotify.soloist`) с закрытых серверов Spotify (`https://soloist-builds.spotifycdn.com/soloist_release_osx_arm64.tar.gz`), подписанный приватным сертификатом Apple команды Spotify (`2FNC3A47ZF`).
   * Soloist запускается как дочерний процесс и общается с клиентом через локальный Unix-сокет. Так как этот бинарник создан самой Spotify, он обладает приватными ключами и легитимным DRM-рукопожатием, что исключает ошибку `AesKeyError 0 1`.
   * **Ограничение:** Spotify выпускает Soloist исключительно для macOS (Apple Silicon ARM64) и требует персональный ключ из Spotify Developer Dashboard (`developer.spotify.com/dashboard/soloist`). Под Linux готового бинарника Soloist на CDN нет (HTTP 404).

---

### 3.2. Варианты реализации звука для Linux в SpotifyLight

1. **Вариант А: Режим Spotify Connect (Архитектура Kinrox до v0.5.0)**
   * Самый надежный и 100% стабильный способ работы со Spotify без нарушения DRM и бана аккаунтов.
   * Приложение работает как полноценный плеер со своим интерфейсом, локальным кэшем, очередью и регулятором громкости, отправляя команды воспроизведения на выбранное устройство Spotify Connect (телефон, умная колонка, либо фоновый официальный демон).
   * Таймлайн, прогресс и состояние воспроизведения зеркалируются в Slint UI в реальном времени.

2. **Вариант Б: Фоновый Spotify Connect Receiver (`Spirc` через Librespot)**
   * Клиент регистрирует себя в локальной сети как официальный Spotify Connect Receiver («SpotifyLight Player»).
   * При передаче потока на себя через протокол Connect дешифрование обрабатывается по протоколу Connect Session, что на поддерживаемых профилях позволяет выводить звук напрямую в PulseAudio/PipeWire.

3. **Вариант В: Headless Spotify Web Playback SDK Runner**
   * Запуск легковесного headless-демона (без оконного WebView и тяжелого Electron) с официальным `https://sdk.scdn.co/spotify-player.js`.
   * Web Playback SDK получает официальные Widevine-ключи от серверов Spotify и транслирует PCM-звук в PulseAudio. Полностью легитимно, работает для всех аккаунтов.

## 4. Поэтапный план реализации нового приложения

### Этап 1: Фундамент ресурсов и дизайн-токенов
- Подключение оригинальных шрифтов `SpotifyMixUI` и `CircularSp-Cyrl` в Slint-конфигурацию.
- Внедрение токенов цветов и отступов из `xpui-snapshot.css`.
- Замена псевдо-иконок на оригинальные векторные SVG.

### Этап 2: Аудио-конвейер и воспроизведение
- Перевод аудио-движка `src/audio/engine.rs` на PipeWire/PulseAudio sink.
- Верификация чистого звука на тестовой виртуальной машине.

### Этап 3: Роутер и разделение поисков
- Реализация `Router` (`Home`, `Search`, `Playlist`, `Album`, `Artist`, `LikedSongs`).
- Привязка верхней поисковой строки к глобальному каталогу (`SearchView`).
- Добавление локальной лупы/фильтра внутри сайдбара «Моя медиатека».

### Этап 4: Правая панель очереди (`RightDrawer`) и история
- Полная верстка панели очереди по эталонному скриншоту `artist+current_play_queue.png`.
- Подключение эндпоинта `/v1/me/player/recently-played` для секции недавних треков.

### Этап 5: Каскадные контекстные меню и действия над объектами
- Исправление архитектуры кликов в `context_menu.slint` (удаление блокирующего `TouchArea(down)`).
